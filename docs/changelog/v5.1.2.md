# Changelog — v5.1.2

_Release de reemplazo de `v5.1.1`: mantiene compatibilidad con la API existente y suma fixes y
mejoras pendientes. Estado: **en preparación** — es la `latest` del sitio, pero todavía no es la
versión final._

## Objetivo

Reemplazar la release publicada con el tag `v5.1.1` por una versión que incluya estos fixes y las
mejoras que entraron después del corte original. No hay cambios de compatibilidad para quien ya
consume la lib, salvo el método `open()` de `cu-side-over`, que nunca funcionó (ver abajo) y pasa a
llamarse `show()`.

## Componentes

**Agregado**

- `cu-autocomplete`: nueva prop `loading` (atributo `loading` en el custom element), como en
  `cu-select`: muestra el spinner de carga en el panel de sugerencias mientras se buscan los items.
- `cu-number-input` / `NumberInput` (componente nuevo): input numérico con `modelValue` numérico
  (`null` es el campo vacío, nunca `""`), `min` / `max` / `step`, `showControls` (botones − / +),
  `showStepSelect` + `steps` (el select de paso es el `Select` de la librería) y atajos `↑` / `↓`.
  El valor se clampea a `min` / `max` en cada cambio. Métodos `get` / `set` / `reset` / `focus` /
  `increment` / `decrement` y eventos `update:modelValue`, `change`, `increment` y `decrement`.
  Incluye fichas vanilla y Vue, demos vivos y baseline de contrato.
- `cu-select`: nueva prop `readOnly` (atributo `read-only` en el custom element). Bloquea la
  apertura del dropdown y el cambio de selección; el control sigue enfocable y no se atenúa.
  `set()` / `reset()` programáticos siguen funcionando. Actualizados ficha, skill, tests y
  baseline de contrato.
- `cu-table` / `AdvancedTable`: la prop `actions` del dropdown "…" acepta un array **o** una función
  `(row) => ButtonConfig[]`, así se decide por fila qué acciones mostrar. Cada acción acepta
  `hidden(row)` y `disabled` como booleano o `(row) => boolean` (el mismo criterio aplica a la
  columna `buttons`); si la fila queda sin acciones visibles, el toggle "…" no se renderiza.
- `cu-switch`: nueva prop `labelPosition` (`'start' | 'end'`, default `'end'`; atributo
  `label-position`) para ubicar la etiqueta a la izquierda del track.
- Tokens de estado: nuevo grupo `alpha` en la config del tema (mismo nivel que `shadows`), que
  `cu-tokens` emite como `--cu-alpha-disabled` (0.7), `--cu-alpha-muted` (0.5),
  `--cu-alpha-subtle` (0.6) y `--cu-alpha-faded` (0.4). Los componentes los consumen con fallback
  (`var(--cu-alpha-disabled, 0.7)`), así un CSS de host viejo —sin estos tokens— se sigue viendo
  igual.
- `cu-divider` / `Divider` (componente nuevo): separador de una línea, `horizontal` o `vertical`,
  con `label` (texto centrado sobre la línea) o contenido rico en el slot `default` (tiene
  prioridad). `variant` (`solid` / `dashed` / `dotted`) y `color` semántico, que resuelve el trazo
  con `--cu-color-{color}-subtle-border` del tema activo. Sin label ni slot es un `<hr>`
  horizontal; con contenido es `role="separator"` con las líneas decorativas `aria-hidden`; en
  vertical suma `aria-orientation="vertical"` y toma el alto del contenedor. No emite eventos ni
  expone métodos. Incluye fichas vanilla y Vue, demos vivos, receta y baseline de contrato.

**Arreglado**

- `cu-date-picker`: el click en el `label` ahora enfoca el trigger además de abrir el panel (antes
  sólo abría). El label ya se renderizaba con `Label`, pero sin foco; ahora el trigger recibe el
  foco real, como un input con su label.
- `cu-card`: los slots `media`, `header` y `footer` ahora funcionan también en el custom element.
  Antes los bloques se renderizaban condicionados a `$slots`, que en un custom element está vacío
  (el contenido vive en el light DOM del host): el `<slot>` nunca existía y el contenido quedaba
  afuera. Ahora la presencia se detecta sobre el slot real (`assignedNodes`) y los bloques vacíos se
  ocultan sin ocupar lugar.
- `cu-card`: el contenido largo ya no desborda la tarjeta ni la página. El cuerpo del layout
  horizontal puede encogerse (`min-width: 0`) y las palabras/URLs largas envuelven
  (`overflow-wrap: anywhere`) en lugar de recortarse contra el borde; la tarjeta y el host del
  custom element no crecen más que su contenedor (`max-width: 100%`). En el custom element además
  se arregló el `:host`: un `;` después de `@unocss-placeholder` hacía que el parser descartara la
  regla siguiente, así que el host nunca aplicaba ni `display: block` ni su ancho máximo.
- `cu-card`: en la doc servida la tarjeta ya no se derrama fuera del recuadro del demo. La causa no
  estaba en el componente sino en el **contenedor de los demos** (`.cu-demo--stack`): al pasar a
  `flex-direction: column` sin resetear el `flex-wrap` heredado quedaba un flex *multi-línea de
  columna*, que con altura automática encoge cada item (el host del custom element) por debajo de su
  contenido; la tarjeta quedaba más alta que su host y se pintaba sobre lo que viene abajo. El demo
  en columna pasa a una sola línea (`flex-wrap: nowrap`).
- `cu-calendar`: mismo arreglo del contenedor de demos. El calendario quedaba hasta 346 px más alto
  que su host (a 900 y 1400 px) y se derramaba sobre el texto siguiente: los días se superponían con
  la línea de «Seleccionado» y con el párrafo de la sección.
- `cu-label`: el click **enfoca y activa** el control real: si es un `checkbox`/`radio` (un
  `Checkbox`, un `Switch`) lo togglea una vez, como un `<label>` nativo; un campo de texto, `select`,
  etc. sólo se enfoca. Si el click nace dentro del control, no se intercepta (no hay doble toggle).
  Antes se escuchaba sólo en el texto y hacía `focus()` sobre el host del custom element, que no es
  focuseable, así que el foco nunca llegaba al `<input>` del shadow root. Ahora el click se escucha
  en el `<label>` completo; sin `for` resuelve solo el primer control del slot entrando a su
  `shadowRoot`, y con `for` además expone el atributo en el `<label>` (asociación nativa). El emit
  `click` cubre todo el label. En Vue también funciona con controles cuyo root no es un campo
  (`Checkbox`, `Switch`): se busca el control focuseable dentro del componente.
- `cu-number-input`: el select de paso usa el `Select` de la librería (antes un `<select>` nativo),
  así hereda color, tamaño y variante del resto del control.
- Estados deshabilitados: `Input`, `Textarea`, `ColorPicker` y `EditableTableCell` consumen los
  tokens `--cu-alpha-*` en vez de valores sueltos. Los campos quedan en 0.7, igual que `Button`, y
  `ColorPicker` / `EditableTableCell` dejan de apilar opacidad (antes el efectivo era 0.25 / 0.20;
  ahora 0.70 / 0.40).
- `cu-switch`: el hover del switch **encendido** usa la variante sólida del color
  (`--cu-color-{color}-hover`, un poco más oscuro) en vez de `ghost-hover` (el color al 10 % de
  opacidad), que lavaba el track casi a blanco/gris. El `:active` encendido usa
  `--cu-color-{color}-active`. El track apagado mantiene su hover sutil
  (`--cu-color-neutral-ghost-hover`).
- `cu-switch`: el atributo/prop `label` ahora renderiza su texto aunque el host no tenga hijos. El
  wrapper CE pasaba siempre un slot `default` vacío, así que el componente interno nunca caía al
  fallback del `label`; ahora sólo pasa el slot cuando el host tiene contenido real (ignora
  espacios y comentarios, y reacciona si el contenido se agrega después del mount). El slot
  `default` sigue teniendo prioridad cuando existe contenido.
- `cu-side-over`: abrir por código ahora se hace con `show()`. El método `open()` no podía funcionar
  porque la prop booleana `open` define `el.open` en el custom element y lo tapaba; el demo de la
  doc construida fallaba con `t.open is not a function`. `open` sigue siendo el atributo/prop
  booleano (mismo patrón que `<dialog>`), y `show()` es el método que abre el panel. Se
  actualizaron la ficha vanilla, el partial de métodos y los demos de la versión.
- `cu-side-over`: el panel del custom element ahora se renderiza dentro de su shadow root (teleport
  desactivado) para que el slot del host se proyecte. Antes el `<slot>` se teleportaba al `body` y
  el contenido quedaba vacío. En Vue se mantiene el teleport a `body`; la nueva prop `teleport`
  (default `true`) permite controlarlo.
